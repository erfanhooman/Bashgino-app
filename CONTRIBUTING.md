# Contributing

Android client for Bashgino. Released independently from the web/API repository
(`Bashgino`); nothing here can deploy a server.

## Branches

| Branch | Purpose | Produces |
| --- | --- | --- |
| `develop` | integration; CI runs on every push | nothing |
| `main` | approved code | a distributable APK + AAB on each version tag |

- `main` moves through a pull request from `develop` with CI green.
- Never commit directly to `main`.

## Releases

```bash
git checkout main && git pull
git tag -a v1.2.0 -m "Bashgino Android 1.2.0"
git push origin v1.2.0
```

`android-release.yml` then: resolves `versionName`/`versionCode` from the tag,
refuses to build without the upload key, runs the same checks as CI, generates
the native project, builds a signed APK and AAB, **verifies the APK is not
debug-signed**, and attaches both to the GitHub Release.

**Marketplace submission is manual.** Nothing is uploaded to Google Play, Myket
or Bazaar by any workflow — that stays a human decision.

## Never commit

- `android/` or `ios/` — generated by `expo prebuild` (Continuous Native
  Generation). Configure native behaviour in `app.json` and config plugins.
- Keystores: `*.jks`, `*.keystore`, `*.p12`, `*.pem`, and the `.env` files that
  hold real values. The upload key lives in GitHub Secrets only.
- `node_modules/`, `.expo/`, `dist/`, build output, `*.apk` / `*.aab`.

`expo-env.d.ts` is generated by Expo and gitignored; CI works without it.

## Native dependencies

Always install with Expo's resolver so the version matches the SDK:

```bash
npx expo install <package>     # never npm install for native modules
```

After adding a library with native code, the app needs a development build
(`npx expo run:android`), not Expo Go.

## Checks (what CI runs)

```bash
npm ci
npm run typecheck      # tsc --noEmit
npm run lint           # expo lint
npm run tokens:check   # design tokens match design/globals.css
npm test               # jest
npx expo prebuild --platform android --no-install   # native project still generates
```

`npm run verify` runs the first four in one go.

## Design tokens

`design/globals.css` is a **vendored snapshot** of the web app's
`frontend/src/app/globals.css`. When the web design system changes:

```bash
cp ../Bashgino/frontend/src/app/globals.css design/globals.css
npm run tokens:sync
git add design/globals.css src/theme/tokens.generated.ts
```

`tokens:check` fails the build when the generated file is stale, so drift is
visible rather than a colour that "almost" matches.
